A private file is a
permission decision

ILLUSTRATIVE ARTICLEPublished: 25 Oct 2026 · sampleUpdated: 25 Oct 2026 · sample3 min read

Uploading a document answers where it lives. It doesn't answer who should be allowed to read it. That is a separate decision.

On this pageStart with the boundaryMake the states explicitCheck the path to public

Start with the boundary

A useful document library has two different jobs: keeping files safe and sharing selected files. Giving both jobs the same default permission makes it too easy for an upload to become a publication.

Start with a private object. Keep its title, owner, and intended visibility in a separate record. A public download should be the result of an explicit publishing step.

A small distinction that matters
A hidden link is still a link. If someone has a public download URL, removing it from a page doesn't make the underlying file private.

Make the states explicit

The first version can use a small set of states. The important part is that an upload begins as private, and that changing a metadata field alone cannot expose the original file.

document.ts · TypeScript
type Visibility = 'private' | 'public';

const document = {
  title: 'An experiment worth keeping',
  visibility: 'private' as Visibility,
  storagePath: 'private/owner-id/documents/experiment.pdf',
};

// A data model is not an authorization check.
// Enforce access at the storage and server boundaries.

Type definitions help describe the workflow. Storage rules and backend authorization enforce it. These are different responsibilities, and both need to be checked.

Check the path to public

Keep private originals separate from public copies. Review the file before publishing it, and make the public copy a deliberate action with a record of what was shared.

Test with an unauthenticated request as well as an owner session. A successful owner download tells you very little about whether the public boundary is working.
